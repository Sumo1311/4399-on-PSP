# 双刃战士 B155 画面修补测试报告

2026-11-16，基于已交付 B154。针对实机反馈的金币侧面难辨认、杂兵和 Boss 在死亡表现完成前消失，交付单机 B155 测试包。实机复测待用户完成，尚未达到稳定 60 帧。

## 修补

- 静止金币从侧面第 2 帧改为正面第 8 帧。原作随机脚本、随机序列、停止状态与碰撞边界保持一致，素材文件未修改。
- 原判断只检查血量归零，立即隐藏敌人和影子。现在同时确认 alive=false、landed=true、deadCount<60，才隐藏落地尸体；击飞死亡过程保留身体并稳定渲染 Alpha。特殊 Boss 缺少明确落地或倒计时字段时保留原作显示。
- 仅修改 visual_policy.js、src/corpse_visibility.hpp、src/render_bridge.cpp、src/render_mirror.inc。原作逻辑、物理、输入、RNG、音频、存档和网络协议代码未修改。

## 验证

- 实际 QuickJS 32 项边界检查及 ASAN/UBSAN 通过：活着且零血量、死亡腾空、落地、60/59 倒计时边界、特殊 Boss、复活，以及缺字段/getter/proxy 安全回退。LeakSanitizer 未启用。
- 原作金币脚本 90 步检查通过。解码资源及原生画面确认金币正面可见。
- B154/B155 相同输入各 1700 帧，实际原生截图显示：金币由侧面变为正面，被旧策略隐藏的死亡击飞身体恢复。两版各 1700 项镜像/参考遍历绘制命令一致。
- B155 原输入回放 7250 帧，覆盖实际 Brute Boss 死亡。7250 项镜像/参考遍历检查通过，玩法/RNG/音频逐行保持原资格前缀一致。7 项既有捕获脚本异常的 tick、消息和栈与原资格记录一致。额外只读显示见证中的对象分配 UID 因宿主/渲染实例化存在差异，其他见证字段一致。
- 原生运行配置：PSP-2000、64 MiB、333 MHz CPU，应用总线 166 MHz、480×272、正常速度、音频开启、真实 I/O、关闭跳帧与加速。配置和原始记录附在 qa 中。
- 单机及 WLAN 源码独立重建，EBOOT 与各自冻结版本逐字节一致。

## 同输入性能

两版顺序运行相同 1025 次输入、2600 个源逻辑步。分别连续空闲 30.94/30.01 秒后启动，外来模拟器样本为 0。重战斗窗口为 [1330,1700)，共 370 步。

| 指标 | B154 | B155 |
| --- | ---: | ---: |
| 完整步平均 | 29.107 ms | 29.004 ms |
| p95 | 38.703 ms | 38.656 ms |
| p99 | 55.951 ms | 57.609 ms |
| 最大 | 69.430 ms | 59.641 ms |

该单组对照用于观察修补后的开销，平均基本持平；没有据此宣称性能提升。标记输出不等于实机显示帧率，PPSSPP 不能证明 PSP 的 CPU 缓存、GE/显存/存储带宽及真实输入延迟。长帧仍存在，稳定 60 帧未达成。
