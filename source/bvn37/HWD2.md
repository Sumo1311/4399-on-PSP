# HWD2 资源读取诊断候选

已记录用户的实体 PSP 失败组合：市丸银对普通鸣人、贾卡杰克援助、十三番队，弹窗 NARUTO1.BVF / ERR=0 / FIGHTER OPEN。NARUTO1 是普通鸣人同一角色家族内的一尾形态，入场时会预载。

hwd1 同一程序与数据在 PPSSPP PSP-1000 模式、默认时钟、原始分辨率、不跳帧下，4 组援助搭配/双方互换均能进入战斗。文件与全部贴图解码核验通过，因此尚未确定实机根因。

本候选恢复市丸银待机中的 9 个透明姿态，保留原先正常的 3 个姿态，全部其他动作及攻击/碰撞/事件/时序保持一致。同时细化读取诊断，不改变资源读取顺序。普通战斗帧仍不写日志。错误会显示具体读取/校验步骤；在清理本轮资源、等待全部原有异步读句柄释放后，单独计算失败文件的大小及 CRC32，和固定发行资源作对比。最后的文件校验结果仅说明这次复读到的字节是否匹配，不能单独定位记忆棒硬件或游戏代码。

FILE CRC OK 表示失败后文件复读与已知资源一致，需要结合失败步骤、短读标志与内存记录检查运行状态。FILE CRC DIFFERENT 表示复读字节或长度与发行文件不同。FILE CHECK FAILED 表示复读未能完成或路径没有校验条目。

默认保留 hwd1 的原预读取方式。在标题菜单按一下 R 即可切换同步 stdio 对照；启动手柄检测先初始化并等待新采样，仍保留按住 R 和空标记文件 BVN_SYNC.IO 的入口。此对照仍用于定位，未作为已验证修复。

BVN_DIAG.LOG 还包含最后读取期望/实际字节数、EOF/ferror、文件长度、元数据签名和失败时内存。每次启动覆盖日志，请退出后先保存再重开。

本目录继承 hwd1 的 build.py；其 CONTENT_MANIFEST 指向本候选 EBOOT，其中 198 个数据文件保持 hwd1 原件，GIN.BVF 修复待机图形，构建使用 BVN_RESOURCE_DIAGNOSTICS=ON。hwd1 正式 Release 尚未被本候选替换。

用户已确认 PSP-2000，贾卡杰克仅为玩家援助；hwd1 按住 R 的尝试仍显示 ORIGINAL IO，因此该次并非有效同步读取比较。
